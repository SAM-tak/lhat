# Lua 比較の追加最適化

基準は `be4352a`。次の3案を順番に実装・測定した。1.1倍は目標とし、速度改善があれば採用する。
ケース・manifest・入力・期待結果・GC設定は変更していない。
L^ / Luau は VS 付属 Clang 22.1.3、Lua 5.5.1 は MSVC 19.51.36260.0。
測定は Release、PGO / JIT / デバッガ無効。

## 採用した変更

1. 添字代入のレジスタコピー削減。
   通常の代入でキーと右辺がユーザーコードを実行しない場合、ローカル変数の受け手とキーを直接使用する。
   右辺のローカル参照も不要なコピーを省く。
   呼び出しなどが変数を書き換える場合は、元の受け手とキーのスナップショットを維持する。
   単独試行の時間にはばらつきがあり、この変更だけの短縮率は断定しない。
2. 関数呼び出しの軽量化。
   通常のスクリプト関数を早く判別して既存の呼び出し処理へ進める。
   引数数、可変長引数、スタック容量などの検査は共有する。
   呼び出し先の一時領域は nil タグだけをクリアし、小さい領域のクリアをインライン化する。
   開いた upvalue がない戻り処理では、閉じる関数の呼び出しを省く。

## 採用しなかった変更

3. 固定フィールドの読み書き専用化。
   複合代入の読み取りに GETMEMBER、書き込みに新しい SETMEMBER を使用し、キーのロードを省いた。
   汎用代入と処理を共有する版、その後に専用の更新処理を持つ版を試した。
   最終候補は正しさのテストを通ったが、交互測定でフィールド更新の短縮を確認できず、
   2までの変更と比べて関数・再帰とエンティティ更新が遅くなったため取り除いた。
   最終コードに新命令やバイナリ形式の変更は残していない。

## 変更前との交互測定

以前の測定との単純比較を避けるため、基準コミットも同じコンパイラとオプションで作り直した。
変更前・1〜2の変更後・1〜3の変更後・Lua を、ケースごとに固定 seed で順序を入れ替えて実行。
3プロセス群、各2ウォームアップ・5サンプル、同一ケース内は全実装で同じ rounds を使用した。
既存の run.py の invoke を使い、期待結果の検証も維持した。

単位は µs / round。値は各プロセス中央値の中央値。
「短縮」は変更前に対する1〜2の変更後の時間の減少率で、負数は増加。

| ケース | 変更前 | 1〜2の変更後（採用） | 1〜3の変更後（不採用） | 短縮 |
| --- | ---: | ---: | ---: | ---: |
| 算術・分岐 | 114.81 | 119.81 | 113.84 | -4.4% |
| 関数・再帰 | 615.71 | 468.31 | 528.80 | 23.9% |
| 配列 | 189.61 | 167.86 | 164.37 | 11.5% |
| フィールド更新 | 668.40 | 681.98 | 695.57 | -2.0% |
| テーブル生成 | 433.02 | 413.41 | 398.96 | 4.5% |
| エンティティ更新 | 1366.93 | 1297.18 | 1477.60 | 5.1% |

関数・再帰と配列で改善が見られた。算術・分岐、フィールド更新には改善を主張しない。
プロセス間のばらつきがあり、上記の短縮率は点推定。信頼区間や任意のプログラムでの保証ではない。

## 採用コードと Lua の標準測定

5プロセス、3ウォームアップ、10サンプル、目標250ms。単位は µs / round。
Lua 比はこの測定内の中央値同士で求める。交互測定や以前のセッションの絶対時間とは分けて扱う。

| ケース | L^ | Lua | L^ / Lua |
| --- | ---: | ---: | ---: |
| 算術・分岐 | 118.34 | 91.02 | 1.300 |
| 関数・再帰 | 511.63 | 311.82 | 1.641 |
| 配列 | 162.30 | 103.99 | 1.561 |
| フィールド更新 | 721.42 | 397.46 | 1.815 |
| テーブル生成 | 461.07 | 300.50 | 1.534 |
| エンティティ更新 | 1335.85 | 750.86 | 1.779 |

1.1倍は未達。中央値では全6ケースが2倍未満で、
各ケースの「最も遅い L^ のプロセス中央値 / 最も速い Lua のプロセス中央値」も2未満だった。
これは今回の測定範囲の確認であり、将来の測定の保証ではない。

## 検証と成果物

- 最終採用コードで JIT 無効・有効それぞれ90テストすべて成功。
- 右辺の呼び出しが受け手やキーを変更するケースを追加検証。
- JIT のメンバ検索呼び出し2か所を現在のAPI（受け手のスロット番号）に合わせ、ビルド不整合を修正。
- JIT stencil を再生成し、生成バイト列の変更はなく、ソースハッシュのみ更新。生成元のハッシュ検査も成功。
- ベンチマークは標準・境界入力と全ウォームアップ・測定の期待結果を検証。

生データは Git 管理外の `results/` に保存した。
`trial1-register-forwarding/`、`trial2-calls/`、`trial3-members/`、`trial3-final/` が順次試行。
`variants-interleaved/` は交互測定の全サンプル・バイナリハッシュ・実行スクリプト。
`selected-final/` は採用コードの標準測定（5プロセス、3ウォームアップ、10サンプル、目標250ms）。
比較用ビルドと不採用案の差分もローカルに保持している。
