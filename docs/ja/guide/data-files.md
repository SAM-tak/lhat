# データファイル（LTON）

設定やゲームデータのような純粋なデータは、`.lh` ではなく LTON（L^ Table Object Notation、拡張子 `.lton`）で書けます。
LTON はテーブルリテラルの波括弧の内側だけを書く形式です。コメント、文字列、数値、式の書き方は L^ と同じで、同じ字句・構文解析器が読みます。

## データを書く

`sample/docs/modules/settings.lton` は、ウィンドウの設定を書いたファイルです。

<<< @/../sample/docs/modules/settings.lton{lhat}

外側の `{` `}` と `return^` は書きません。要素は `,` で区切り、末尾の `,` も許されます。
要素の形はテーブルリテラルと同じで、位置の要素、`名前 = 値`、`[キー] = 値` が使えます。
空のファイルは空のテーブルです。

値は計算済みである必要はありません。`480 * 2` のような算術や、`..` による文字列の連結を書けます。

## 読み込む

`std.lton.load` はファイルを読み、テーブルを返します。

<<< @/../sample/docs/modules/settings.lh{lhat}

返るテーブルの型は `t^{}` です。中身は検査時にはわからないため、`conf.width` とは直接書けません。
`conf["width"]` のように添字で読むか、`fits^` で形を確かめてから、その分岐の中でメンバとして使います。

パスは読み込む側のファイルではなく、ホストのローダーが解決します。CLI では作業ディレクトリが基準です。
リポジトリのルートで次を実行すると、`960`、`demo 518400` を表示します。

```sh
lhat sample/docs/modules/settings.lh
```

文字列から読むときは `std.lton.parse` を使います。どちらも関数 `f^` で、読み込みそのものは副作用を持ちません。
読めないファイルは `LtonError.CannotRead`、検査を通らない本文は `LtonError.Rejected` になります。

## `.lh` との使い分け

同じデータは、`public^` で値を公開する `.lh` のモジュールにも書けます。

```lhat
module^demo.settings
public^let^window = { title = "demo", width = 480 * 2, height = 540 }
```

`require^` で読み込めば `settings.window.width` と直接書けます。検査器がリテラルの中身から型を組み立てるためです。
LTON は次の点で異なります。

- **型を生成しない。** 読み込み結果は常に `t^{}` です。データが大きくなっても、型検査やエディタが扱う型は大きくなりません。
  `.lh` で書くと、データの形がそのまま型になります。
- **効果を持てない。** 本文は関数 `f^` の本体として検査されるため、手続き `p^` は呼べません。
  ホストが束縛した名前も見えません。
- **実行時に読み、書き出せる。** パスは文字列の値なので、読むファイルを実行時に選べます。
  `std.lton.stringify` と `std.lton.save` でテーブルを LTON に書き出せ、読み直すと同じ内容のテーブルになります。
- **エディタは文法だけを検査する。** 言語サーバーは開いている `.lton` の構文だけを確認し、型の情報を作りません。

コードから型付きのメンバとして使いたい少量の定数は `.lh`、外部から差し替える設定や、ツールが読み書きする大きなデータは LTON が向いています。

## 列挙体を書く

LTON の先頭には `import^` と `require^` を書けます。取り込んだモジュールの列挙体や定数を値として使えます。

```lhat
import^game.code

{ op = game.code.Instruction.Push, arg = 1 },
{ op = game.code.Instruction.Load, arg = "x" },
```

取り込みは要素より前にだけ書けます。`let^c = import^game.code` のように別名も付けられます。
取り込まなかった名前は一つも見えません。
`std.lton.stringify` が列挙体を含むテーブルを書き出すときは、必要な取り込みを自動で先頭に出力します。
