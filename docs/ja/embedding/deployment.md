# リロードと配布

## 独自のファイルローダ

`LhatProgramLoader` は UTF-8 のパスを受け取り、内容とバイト数を返します。
アプリケーションの仮想ファイルシステム、アーカイブ、エディタの未保存バッファなどへ接続できます。
ファイルがなければ NULL を返します。

返すバッファは `lhat_alloc` で確保し、Program に所有権を渡します。
Program が `lhat_free` で解放するため、スタック配列、`std::string::c_str()`、別アロケータのバッファをそのまま返しません。
ソースには終端 NUL の余白も用意し、`length` には終端を含めません。
ローダが NULL の Program はファイルを自動では読みません。

`require^` の依存先は現在のユニットのパスを基準に解決されます。
エディタ、実行時、配布物で同じ論理パスを使えるようにします。

## まずは再起動できるリロードを作る

開発の最初は、スクリプト状態を捨てて Machine を作り直す方式でも十分です。
更新をフレーム境界で適用し、ワーカー停止とエンジンの参照の後始末を決めます。
実行中のコールバックの途中で、コードやインスタンスを破棄しないでください。

## 状態を残してコードを再読込する

`lhat_reload(program, path, machines, machine_count)` は、変更ユニットとそれに依存するユニットの無効化、再検査、再コンパイル、
古いモジュールの登録解除、保持されていない旧コードの回収をまとめて行います。
対象 Program をインストールした全 Machine を渡し、実行が止まった安全な境界で呼びます。

- 戻り値 0 は内容が変わっていない状態です。
- `SIZE_MAX` は Program に該当するパスがない状態です。
- それ以外は無効化したユニット数で、成功を示す bool ではありません。診断とコンパイル状態を別途確認します。

再検査・コンパイルに失敗しても、既存の古いクロージャは旧コードで動けます。
成功しても、ホストが持つ既存インスタンスやコールバックが自動的に新しい実装へ差し替わるわけではありません。
モジュールを再実行して新しい公開値を取り出し、ホストの参照を交換し、必要な状態を移します。

古いコードを手動で捨てる `lhat_program_discard_retired` は、全 Machine の古いクロージャや中断中のコルーチンがなくなったときだけ使えます。
通常は `lhat_program_discard_unheld` を使い、全対象 Machine が停止しているときに回収可否を判断させてください。
詳細は[C API](../api/program.md#リロード)を参照してください。

## 配布形式を決める

| 形式 | ホストに必要なもの |
| --- | --- |
| ソースを配る | フロントエンドを含むランタイムと、通常の API 登録 |
| コンパイル済みユニットを配る | 同じビルド指紋に対応するランタイムと、同じ API 登録 |
| VM のみで配る | 上記に加え、フルビルドで生成したシグネチャ表 |

フルビルドで検査・コンパイルした各ユニットを `lhat_unit_write_binary` で書き出します。
読み込みは同じローダと `lhat_program_check` の入口を使い、先頭のバイトからバイナリと判別します。
一つの Program でソースのユニットとバイナリのユニットは混在できません。
依存ユニットも含めて書き出し、同じ論理パスで配置します。

VM のみのビルドは `LHAT_WITH_FRONTEND=OFF` にし、`LHAT_BUILD_LSP=OFF` にします。
文字列のシグネチャを解析できないため、フルビルドの同じホストから `lhat_program_write_signatures` で表を作り、
配布版は **API 登録前** に `lhat_program_read_signatures` で読み込みます。
その後、通常どおり同じホスト API を登録します。

`lhat-host.json` はエディタ用の JSON です。VM のシグネチャ表やコンパイル済みユニットの代わりにはなりません。
バイナリは長期互換の交換形式として扱わず、対応するランタイムと登録内容で再生成してください。
