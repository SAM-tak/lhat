# テーブルとオブジェクト

## テーブルとは

テーブルは、**配列と辞書を一体にしたデータ構造**です。
値を順に並べて添字で取り出す配列としても、名前などのキーに値を対応付ける辞書としても、同じテーブルを使います。
配列用と辞書用に別の種類を使い分ける必要はなく、1つのテーブルに両方の要素を混在させることもできます。

```lhat
let^array = {10, 20, 30}
let^dictionary = {name = "L^", version = 1}
let^mixed = {10, 20, name = "scores"}

print(array[0])           # 10
print(dictionary.name)    # L^
print(dictionary["name"]) # L^: same key as .name
print(mixed[1], mixed.name) # 20 scores
```

配列部分の添字は0から始まります。辞書部分は `t.name` や `t[キー]` で参照します。
`t.name` と `t["name"]` は同じ要素を指します。

## テーブルリテラルと要素

テーブルは配列部分とキー付きの部分を持ちます。

| 要素の形 | 意味 |
| --- | --- |
| `{値1, 値2}` | 0から始まる配列要素 |
| `{名前 = 値}` | 名前をキーにした要素 |
| `{[式] = 値}` | 計算した値をキーにした要素 |
| `{名前:型 = 値}` | 要素の値に型注釈を指定 |

非負整数の添字は配列位置、それ以外はキーです。`t[-1]` は最後の配列要素ではなく、キー `-1` の参照です。
キーに `nil^`・NaN は使えません。ホスト値を記録するキーには封印済みの箱が必要です。
既存の辞書キーに `nil^` を代入すると削除します。配列への `nil^` は位置を残し、長さを縮めません。
存在が保証されないアクセスの扱いは型に依存します。常に暗黙の `nil^` を返すわけではありません。
既存の配列部分の範囲内の実数添字は `floor(x + 0.5)` で位置へ丸めます。
整数値の `2.0` と `2` は同じキーです。範囲外の非整数キーまで常に配列位置にする規則ではありません。

## 構築済みテーブルへのメンバ追加と更新

テーブルを作った後に名前付きメンバを追加するには、`var^t.bbb = "bbb"` と書きます。
`t.bbb := "bbb"` は既存メンバの更新なので、まだ `bbb` がなければ型検査でエラーになります。
ここでは、名前付きメンバを列挙した通常の構造型について説明します。辞書型の制約がある場合は、後述の規則も適用します。

| 書き方 | メンバがない場合 | 既にある場合 |
| --- | --- | --- |
| `var^t.bbb = 値` | 追加 | 再定義のエラー |
| `t.bbb := 値` | メンバがないエラー | 更新 |
| `var^t.bbb := 値` | 追加 | 更新 |
| `let^t.bbb = 値` | 使用不可 | 使用不可 |

`let^` は名前を束縛するための構文で、メンバの追加には使えません。
一方、`let^t = {aaa = 1}` で束縛したテーブルにも `var^t.bbb = …` で追加できます。
ここでの `var^` は `bbb` を導入するもので、名前 `t` の再代入ではありません。
追加後の更新でも、値は既存メンバの型に適合する必要があります。

<<< @/../sample/docs/reference/table-members.lh{lhat}

`var^t.config.window.width = 800` のような多段の経路では、途中のテーブルがなければ作り、既にあれば同じテーブルを辿ります。
続けて `height` を追加しても、先に作った `width` は残ります。`=` では末尾のメンバは新規である必要があります。

これらは通常のテーブルへの操作です。定義・インスタンスの構造、型注釈を通したアクセス、関数内からの変更には、それぞれの制約があります。
束縛との違いは[メンバの導入と変更](./bindings.md#メンバの導入と変更)、配列への追加・削除は[テーブルの組込み操作](#テーブルの組込み操作)を参照してください。

### 添字による任意キーの追加と更新

実行時に決まるキーには `t[key] := 値` を使います。キーがなければ追加、あれば更新します。
`var^t[key] = 値`・`var^t[key] := 値` は使えません。`var^` によるメンバの導入はドット形式です。

```lhat
let^t = {aaa = 1}
t["bbb"] := 2  # 追加できる
# t.bbb := 2   # エラー: 型に bbb メンバがない
```

::: info ドット形式と添字形式の非対称さ
同じキーへのアクセスなのに書き込みの規則が異なる点は、設計者も不自然だと認識していますが、現状は仕様上の区別です。
ドット形式は名前付きメンバの宣言・更新、添字形式はキーに対応する要素の追加・更新として扱います。
:::

`var^t.bbb = 2` という宣言は型検査器が読み取り、名前付きメンバ `bbb:number^` として静的な型情報に反映します。
実行時に型情報を書き換えるのではないため、同じスコープでは、宣言より前に書いた `typeof^(t).signature` にも `bbb` が含まれます。
型情報に含まれていても、宣言が実行される前にそのメンバの値を読み出せるわけではありません。

添字で追加しても、名前付きメンバ `bbb:number^` が型に追加されるわけではありません。
**辞書の制約 `[string^]:number^` も自動では追加されません。** この例の `typeof^(t).signature` は `t^{aaa:number^}` のままで、`t.bbb` を使えるようにはなりません。

辞書としてキーと値の型を保証したい場合は、生成時に `t^{[キー型]:値型}` を指定します。

<<< @/../sample/docs/reference/table-keys.lh{lhat}

`d[key]` への書き込みはキーを `string^`、値を `number^` と照合します。
この辞書型は特定のキーの存在を保証しないため、読み出しは `number^|nil^` です。`nil^` の代入はキーの削除として使えます。
辞書型では `d.bbb` も文字列キーへのアクセスとして同じ制約に従い、必須の名前付きメンバとは区別します。

## 数え方と文字列

| メンバ | 意味 |
| --- | --- |
| `t.len^`・`t.length^` | 配列部分の長さ。`nil^` の位置も含む |
| `t.count^` | 配列部分とキー付き部分の全要素数 |
| `s.len`・`s.length` | 文字列の拡張書記素クラスタ数 |
| `s.size` | 文字列のバイト数 |

これらは値を表すメンバで、呼び出し括弧は付けません。
テーブルの組込み操作は利用者のキーと区別するためハットが必要です。文字列の組込みメンバは裸の名前です。
`s.substring(...)`・`s.substr(...)`・`s.sub(...)`・`s.at(...)` は文字単位、
`s.chars()` は文字の走査、`s.codepoints()` は Unicode スカラー値の走査です。
`s.sliceBytes(begin, end)` はバイト範囲を半開区間 `[begin, end)` として切り出します。

## テーブルの組込み操作

| 操作 | 内容 |
| --- | --- |
| `clone^()` | 浅い複製 |
| `slice^(開始, 終了)` | 両端を含む範囲の浅い複製。負の位置は末尾から |
| `join^(区切り)` | 文字列・数値の要素を連結 |
| `indexof^(値)`・`contains^(値)` | 要素の検索・有無 |
| `push^(値)`・`pop^()` | 末尾への追加・末尾からの取得 |
| `insert^(位置, 値)`・`remove^(位置)` | 挿入・削除と後続要素の移動 |
| `extend^(配列)` | 配列部分を末尾へ追加 |
| `sort^()`・`stablesort^()` | 整列 |
| `reverse^()`・`move^(…)` | 逆順化・要素の移動 |
| `resize^(長さ, 値)` | 配列の長さの変更 |
| `clear^()`・`assign^(相手)` | 全消去・内容の置き換え |
| `range^(…)`・`reverse_range^(…)`・`range_downto^(…)`・`reverse_iterate^()` | 元の添字と値を返す配列走査 |
| `iterate^()`・`keys^()`・`values^()` | キーと値の組・全キー・全値の走査 |

変更系の操作は受け手を変更します。`pop^`・`remove^` は取り出した値または `nil^`、
その他の上記変更系は受け手自身を返します。
関数内で変更できる受け手は[副作用の規則](./subroutines.md)に従います。

### 引数と境界の規則

- `clone^(方針)` は配列・辞書の各値を `f^any^ -> any^;` の方針に通し、キーは保持します。再帰的な複製は方針自身で書きます。
- `join^()` の区切りは省略できます。要素は文字列・数値に限ります。`indexof^`・`contains^` は組込みの等値を使い、利用者の `op^=` は呼びません。
- `slice^(開始)` は末尾までです。範囲が成立しなければ空のテーブルを返します。
- `insert^(位置, 値)` は非負位置の手前、負位置の後ろへ挿入します。`0` は先頭、`-1` は末尾です。両端の外へ1位置だけ挿入でき、それ以上は異常です。
- `remove^` の負位置は末尾から数えます。範囲外や空の `remove^`・`pop^` は `nil^` で、変更しません。
- `sort^(比較子)`・`stablesort^(比較子)` は負・0・正の数値を返す比較子を取れます。省略時は数値・文字列の組込み順序です。`stablesort^` だけが同順要素の順序を保証します。
- `move^(元, 先)` は1要素を移動します。`move^(元, 終端, 先)` は自分の中の範囲コピー、先頭に相手のテーブルを加えた形は相手からのコピーです。重なりも正しくコピーします。
- `resize^(長さ)` は `nil^` で埋められる要素型に限ります。明示した埋め値でも伸長でき、縮めると末尾を捨てます。負の長さは異常です。
- `assign^` は浅い内容の置き換えで、相手にないキーを消します。同じ定義のインスタンスにも使え、受け手の同一性と定義は保持します。
- `extend^(自分)` は呼んだ時点の配列をもう一度付けます。`clear^` は配列・辞書の両方を消します。

## def^ と生成

### L^ におけるオブジェクト

`def^` から作るオブジェクト（インスタンス）も、テーブルの一種です。
`def^{…}` は、そのテーブルのフィールドの雛形と、インスタンス間で共有するメンバをまとめた定義です。

雛形は `self^{…}` に書きます。通常のメンバメソッドはその外側に置き、第一引数を `self^` にします。
メソッド内では `self^.フィールド名` で自分のフィールドにアクセスします。
`インスタンス.メソッド(引数)` と呼ぶと、インスタンスが `self^` として自動的に渡されます。

`self^` 引数のない関数・手続きは、いわば静的メンバ関数です。
外部からは `定義名.関数名(引数)`、定義内からは `def^.関数名(引数)` で呼びます。
この関数にはインスタンスが渡らないため、そのフィールドを `self^` で参照することはできません。

<<< @/../sample/docs/reference/objects.lh{lhat}

この例の `value` はインスタンスごとのフィールド、`add` と `doubled` は共有メソッド、`double` は静的メンバ関数です。
`c.value` がフィールド、`c.doubled()` がメソッド、`Counter.double(4)` が静的メンバ関数へのアクセスです。

`doubled` の本体では、フィールドを `self^.value`、定義側の関数を `def^.double` で参照しています。
静的メンバは局所変数ではないため、単に `double(…)` と書いては参照できません。定義を指す `def^` を介して `def^.double(…)` と書きます。
`self^` は呼び出されたインスタンス、`def^` はそのメソッドを記述した定義を指します。

### 定義と構築の規則

`def^{…}` は、インスタンスの雛形と共有メンバを持つ定義を作ります。
`self^{フィールド = 初期値}` にインスタンスごとのフィールドを書きます。
共有メソッドは定義側に置き、第一引数に `self^` を書きます。
`self^{…}` の内側にもコールバックフィールドやインスタンス固有メソッドを置けます。
フィールドと共有メソッドを同名にはできません。

`new^型{フィールド = 値}` で明示的な型を指定して生成します。
構造型では追加フィールドも保持します。定義の既定値は雛形から生成ごとに複製します。
既定の生成は `定義.new(...)` でも行えます。`override^new` が置き換えた構築には `定義.new(...)` を使います。
インスタンスはフィールドと受け手を取るメソッドを持ち、静的メンバは定義の側に属します。

定義の内側の `def^` は現在の定義を指し、値位置の `Self^` も同じ定義です。
型位置の `Self^` は自身のインスタンス型を表します。
同じ定義のメンバは記述順によらず見えます。
既定値のテーブル・箱はインスタンスごとに複製し、可変の既定値をインスタンス間で共有しません。
既定の `new` を明示的に置き換えるには `override^`、呼び方を増やすには `overload^` が必要です。

## 合成、上書き、多重定義

`A .. B`（または `A :: B`）で定義を合成します。委譲先と順序は定義時に確定します。
同名メンバは既定で衝突です。意図した置換に `override^`、引数の型による多重定義に `overload^` を使います。
置換は元の契約を保ち、引数を狭めたり戻り値を広げたりできません。
定義の構築を置き換える `override^new` はこの置換可能性の検査の例外です。
多重定義の型は交差で、候補は引数の型や個数で区別できなければなりません。
`abstract^名前:型` は合成先が提供すべきメンバです。未実装の抽象メンバが残る定義は生成できません。
`super^` は上書き前の対応する実装を参照します。多段の `super^^` はありません。

名前を持つ定義同士の合成では、同名でどちらを使うか選べないメンバは曖昧になります。
必要なパートを名前で明示するか、合成先で上書きして解決します。
抽象メンバを同じ定義内の別の宣言で埋めることはできず、合成先で満たします。
未実装の抽象フィールドは `override^new` が構築時に与えて満たすこともできます。
委譲だけでは抽象宣言を満たしません。対応する実装のない `override^` も合成先まで保留できますが、未解決のまま生成できません。
多重定義は戻り値型で振り分けず、重なる引数領域に優先順位を付けて選ぶこともしません。

### 抽象型から具象型へ

`abstract^名前:型` は、その名前と型を持つメンバを要求する宣言で、実装や初期値は与えません。
未実装の抽象メンバが残っている定義は抽象型です。**抽象型を定義したり、未実装のまま合成したりするだけではエラーになりません。**
その状態で `定義.new(…)` などによりインスタンスを生成しようとした時にエラーになります。

次の例では、`HasCount` は `count` フィールドを要求する抽象型です。
合成先でこの要求を満たすと、生成可能な具象型になります。

`FixedCount` は、合成の後ろに置いた `self^{ count = 10 }` で抽象フィールドを満たしています。
名前が同じで、値の型が要求された型に適合する必要があります。型の完全一致までは要求しません。
抽象宣言を満たすフィールドの追加には `override^` は不要です。

`GivenCount` は、`override^new` の中の `self^{ count = initial }` で、構築時にフィールドを与えています。
この方法では、抽象宣言の綴りを元の定義に残したままでも、要求が満たされるため生成できます。
`new` 内に複数の `self^{…}` がある場合、すべてでそのフィールドを与える必要があります。
`overload^new` は既定の `new()` を残すため、この方法で抽象フィールドを満たすには使えません。

構築時に満たせるのは `self^{…}` 内の抽象フィールドです。その外側の抽象メソッドなどは、合成先で実装を与えます。
一部の要求だけを満たしても、ほかに未実装の抽象メンバが残れば引き続き抽象型です。

## delegate^ による委譲

`def^` の `delegate^self^.フィールド` で、保持するオブジェクトの受け手を取るメソッドを自分のメンバとして見せます。
ラッパー自身のメンバが優先し、見つからないときに委譲先へ進みます。
メソッドの `self^` は委譲先の実体です。フィールド・静的メンバ・`new` は委譲しません。
委譲先は連鎖でき、探索途中に同名があればそこで止めます。循環して未発見なら探索を打ち切ります。
合成の後ろで委譲先を指定すれば前の委譲を置き換え、指定しなければ保持します。
委譲を使ってもメンバをコピーせず、保持する欄を差し替えれば以降は新しい委譲先を使います。

型検査で見えるメンバにも同じ探索規則を使います。
ホスト値・ホストデータの参照とコピー、箱の規則は[ホスト型と箱](./host-types.md)を参照してください。

## 列挙体

`enum^名前 { A, B, C = 10 }` は公称の列挙体を宣言します。
メンバはそれぞれ唯一の値で、`=` と `is^` は同じ同一性を調べます。
`.value` は指定した値、無指定なら先頭0からの番号です。整数の明示値の次はその整数の次へ進みます。
`.enum` は所属する列挙体、`.tostring()` はメンバ名です。
型位置の列挙体名は全メンバ、メンバ名はその1つを表し、パターンマッチで全メンバを列挙すれば網羅できます。
宣言後にメンバを追加・置換することはできません。
