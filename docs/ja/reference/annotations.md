# 注釈

## 記法と意味

注釈は宣言にメタデータを付け、ホストへ渡す構文です。
ホストが意味を定め、L^ は登録された契約を検証して情報を保持します。
注釈自身が実行されて宣言を書き換えることはありません。

```text
@名前
@名前(引数, 引数)
宣言
```

`@` と名前の間に空白は置けません。
名前は単純名で、`@game.export` のようなドット付きの名前は使いません。

## 引数

| 形 | ホストへ渡す内容 |
| --- | --- |
| `0`、`-50`、`1.5` | 数値 |
| `"text"` | 文字列 |
| `true^`、`false^` | 真偽値 |
| `NAME` | 名前の綴り。値へ解決しない |

一般の式、実行時の計算、名前付き引数は書けません。
名前引数の `NAME` は、プログラムの定数を評価して渡す記法ではありません。

## 配置と検証

注釈の配置先は単位そのもの、最上位の束縛、`self^{…}` の欄、`def^` のメンバです。
そのうち許される位置は注釈ごとのホスト登録で決まり、任意の文には付けられません。
値をホストへ渡すための注釈は、公開された束縛に付ける必要があります。
名前、引数の種類・個数、配置、重複の可否、排他や併記の条件を型検査で確認します。
未登録の注釈は黙って無視せず、エラーになります。

ゲームエンジンでのエディタ公開や RPC などもホストが意味を与える用途です。
使える注釈は組み込み先のアプリケーションの API を参照してください。

宣言の名前・引数名・注釈は、型から独立した情報としてホストが読み取れます。
ホストは注釈付きの空の手続き本体へ実装を与えることもできます。
これは空の本体とホスト登録の約束に基づくもので、注釈があるだけで一般の本体を無条件に置き換える機構ではありません。
空でない本体はそのまま実行し、注釈のない空の手続きは通常どおり何もしません。
